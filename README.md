# mingtu — 肠道菌群健康顾问

一个面向中国普通用户的肠道微生态科普 RAG 智能体。它做两件事：把证据按可信度分层讲清楚，以及判断什么情况该去看医生。它不做诊断。

这份文档写给接手这套代码的工程团队。读完你应该知道每个模块负责什么、为什么这么切分、哪些地方是刻意不优雅的，以及现在还差什么。部署和运维看 [DEPLOY.md](DEPLOY.md)。

> **快照说明**：本文档对应 2026-08-04 23:24 的工作区状态（`git log` 最新提交 `4002a68`，另有未提交改动）。作答 provider 层和向量后端当时正在改造中，第 8 节标注了当时的实际状态。读到本文档时如果 `agent/llm.py`、`agent/embed.py`、`agent/index.py` 的 mtime 晚于上述时间，以代码为准。架构、安全层、检索层的描述是稳定的。

## 1. 这个智能体是什么

输入一句中文提问，输出一段中文回答加一份来源清单。中间做四件事：

1. **确定性安全筛查** — 先用正则扫消化道报警症状。命中且是第一人称叙述，直接走固定的就医话术，整条链路不经过任何模型。
2. **混合检索** — BM25 + 向量双路召回，RRF 融合，按证据等级/人群/法规属性加权，配额保证特定类别不被挤掉。
3. **作答** — 基于本轮检索到的编号资料写答案，每条实质结论必须标注来源编号。
4. **出口校验** — 校验引用编号真实存在，校验文本不含《广告法》《食品安全法》禁止的健康宣称。不合格带纠正指令重写，重写仍不过就弃答。

定位边界写死在系统提示词里：不诊断疾病、不解读检验报告、不推荐处方药、不评估病情严重程度、不推荐具体品牌。

## 3. 模块职责

### 核心（`agent/`）

| 文件 | 职责 |
|---|---|
| `safety.py` | 三道确定性闸门：输入报警症状筛查、输出违规宣称筛查、急症固定话术。全是正则和字符串，没有模型调用。 |
| `prompt.py` | 中文系统提示词，按段落拼装：人设、定位边界、证据分级、引用规则、合规红线、就医边界、文风。另含本轮资料块的渲染。 |
| `chunker.py` | 把 `research/*.md` 按 Markdown 标题切段，超长段落再按段落/句号切，带 90 字重叠。每块抽取元数据：证据等级、人群、年份、权威性、是否法规、URL。 |
| `embed.py` | 可插拔向量后端：本地 Ollama `bge-m3`（1024 维）优先，其次 OpenAI `text-embedding-3-large`（3072 维）。`backend_id()` 用于把「索引是谁建的」记进 manifest。 |
| `index.py` | 构建索引。jieba 分词（`cut_for_search`）+ 菌株号正则保留，向量化交给 `embed.py`。向量按后端分文件存（`vectors-<backend>.npy`），`load_index` 在后端不匹配时直接报错而不是返回垃圾。 |
| `retrieve.py` | 混合检索。BM25 与向量各取 30 条，RRF 融合，元数据加权，配额选取，近重复抑制。另含 `infer_filters`——不依赖模型的确定性过滤条件推断。 |
| `live.py` | Perplexity 实时补充检索。判断是否需要、发请求、把结果整形成与本地块一样的结构并标 `is_live`。 |
| `classify.py` | 阶段 1 分流与阶段 4 重排。两个都是 LLM 阶段，两个都有确定性兜底。分流部分执行「只升不降」的合并规则。 |
| `core.py` | 编排。串起全流程，实现引用校验、重写循环、来源清单构造。 |
| `llm.py` | 作答模型抽象层。provider 选择、消息格式归一化、结构化输出、自由作答。`core.py` 和 `classify.py` 不感知 provider。 |

### 外围

| 文件 | 职责 |
|---|---|
| `cli.py` | 中文交互式终端入口。彩色输出、等待进度、`/调试` 显示检索细节、`/清空` 重置上下文。存历史前用 `strip_citations` 去掉引用编号——编号只对生成它的那一轮有效，留在上文会诱导模型复用不存在的编号。 |
| `web/server.py` | 网页服务，只用标准库 `http.server`。`GET /`、`GET /health`、`POST /api/chat`。Agent 进程内单例、信号量限流（3 并发）、历史在服务端重新规整、异常不外泄堆栈。 |
| `web/index.html` | 单文件前端。 |
| `run.sh` | 启动前检查：解释器 → 依赖 → 密钥 → 索引 → 安全层 → 入口可导入，然后启动网页服务。索引缺失默认拒绝启动而不是自动重建。 |
| `tools/research.py` | Perplexity 深度研究（`sonar-deep-research`），产出 `research/*.md`。配额耗尽时把提示词落盘成 `.PARKED.txt` 而不是降级到弱模型。 |
| `tests/` | pytest。当前覆盖 `safety.py` 和 `chunker.py`。 |

`agent/` 和 `tools/` 没有 `__init__.py`，靠命名空间包工作，**必须在仓库根目录运行**（`cli.py` 和 `web/server.py` 会自己把仓库根插进 `sys.path`）。

## 4. 为什么这么设计

### 4.1 为什么急症判定不交给模型

这是整个系统里唯一一处模型完全不参与的决策，理由有三条。

**失败模式不对称。** 报警症状漏判的代价是漏诊消化道肿瘤；误判的代价是多说一句「建议去消化科看看」。这两个代价差好几个数量级，所以 `RED_FLAGS` 是刻意过度包含的——它匹配普通人真实的说法（「大便有血」「瘦了好几斤」「厕纸上有血」），不是教科书写法（「便血」「不明原因体重下降」）。宁可多拦，不可漏拦。

**模型的判断不可复现也不可审计。** 同一句「我最近大便有血」，模型可能这次判 emergency 下次判 caution，取决于上下文长度、采样、版本。正则不会。上线一个医疗相关产品，你必须能对监管或法务说清楚「什么输入一定会触发就医提示」，这句话只有确定性代码能兑现。

**模型可以被绕过。** 提示词注入、长上下文稀释、越狱模板，都可能让模型不执行「先给就医建议」这条指令。`screen_input` 跑在模型之前，`escalation_message` 是硬编码文本直接 `return`，中间没有任何模型输出参与，所以注入攻击、检索失败、API 超时、模型拒答都不能让这条路径失效。

实现是**只升不降的合并**（`classify.py`）：

```python
order = {"normal": 0, "caution": 1, "emergency": 2}
if order[floor] > order[result["risk"]]:
    result["risk"] = floor
```

模型可以把 normal 升到 caution、caution 升到 emergency，但**不能**把正则定的 emergency 降回去。模型在这里只有加保险的权力，没有拆保险的权力。

代价是误报：「便血是什么原因造成的」这类纯科普提问，如果句中出现「最近」「一直」等第一人称信号词，也会被 `mentions_self` 判成自述而升级。我们接受这个代价，没有做降级通道。

### 4.2 为什么是混合检索而不是纯向量

因为这个语料里价值最高的事实，恰好是向量最不擅长表示的那一类。

**菌株号。** `DSM 17938` 和 `DSM 9843` 在向量空间里几乎重合——同样的前缀、同样的数字形态、同样的语境。但它们是两个不同的菌种（*Lactobacillus reuteri* 和 *Lactiplantibacillus plantarum* 299v），适应症不同、证据强度不同。纯向量会把它们混在一起，答案里就会出现张冠李戴的菌株，这在本产品里属于严重缺陷。BM25 是精确词项匹配，能把它们分开。剂量（`10^10 CFU`）、法规文号、国标编号同理。

**反过来，纯 BM25 也不够。** 用户说「吃了益生菌还是胀气」，语料里对应的是「产气与腹胀耐受阈值」「低聚果糖 FOS 剂量区间」，词面几乎不重叠，BM25 召不回来，向量可以。

所以两路都要。融合用 **RRF（倒数排名融合）而不是分数加权**：BM25 分数和余弦相似度不在同一量纲上，要混合就得先归一化，而归一化参数会随语料变化——这是个永远调不完的活。RRF 只用两边的排名序，天然免疫量纲问题。

```
score(d) = Σ  1 / (60 + rank_i(d))          再 ×100，便于和元数据加权同量级
```

**元数据加权刻意做得很轻**（A 级 +0.30，法规 +0.45，人群匹配 +0.35）。这些只微调排序，不覆盖相关性。一段完全对题的 D 级证据仍然应该排在完全不对题的 A 级证据前面——因为模型需要看到它，才能对用户说「这个只在动物实验里看到过」。如果直接过滤掉低等级证据，模型就无从判断「证据不足」，只能沉默或者编。

**配额是加权解决不了的问题的补丁**（`_quota_select`）。加权只能在已召回的结果里重排；对于法规类提问，如果法规段落的词面重合度太低，它根本进不了候选池，再高的权重也没用。所以法规问题预留 3 席、特定人群预留 2 席，硬保证这类资料在场。

**近重复抑制**是因为切块有 90 字重叠，同一节的相邻块高度相似，不抑制的话一节内容能占满 rerank 的全部 8 个名额。当前抑制键是 `(source, heading)`。

### 4.3 为什么向量和作答都做成可插拔的本地优先

这是个合规决策，不是成本决策。

这个智能体处理的是中国用户的健康提问——症状描述、用药情况、家族病史。把这些文本发到美国的 API，在《个人信息保护法》和数据出境安全评估的框架下是一个需要专门回答的问题。做成全本地栈是把这个问题**移除**，而不是回答它，这通常才是中国企业客户真正需要的。

所以：

- `embed.py` 优先用本地 Ollama `bge-m3`（多语言/中文检索表现好），取不到再退 OpenAI。
- `llm.py` 的 `active_provider()` 也是本地优先，且在 local-only 模式（默认）下**不回退云端**——本地模型缺失是运维必须看见的错误，不是可以靠悄悄把用户健康问题发去美国来掩盖的事。
- 云端 provider 的偏好序是 Anthropic → OpenAI → Perplexity。这个顺序是质量判断：提示词、证据分级和引用纪律都是照着 `claude-opus-5` 写的。回退存在是为了让服务在没有 Anthropic 账号的机器上也能跑，不代表几个模型可以互相替代。CLI 和网页在非 Anthropic provider 作答时会显式提示。

**混用不同向量后端不是降级，是无意义**——两个不同向量空间之间算余弦相似度得到的是噪声。所以索引按后端分文件存，`load_index` 在后端不匹配时直接报错要求重建。

## 5. 证据分级体系

分级贯穿三层：研究阶段生成、切块阶段抽取、作答阶段传达。

| 等级 | 定义 | 面向用户的说法 |
|---|---|---|
| A | 人体 RCT 的荟萃分析 / 系统综述 | 「这个是有比较扎实的人体研究支持的」 |
| B | 单个人体随机对照试验 | 「有一项人体试验支持，但还需要更多验证」 |
| C | 队列研究 / 观察性研究 | 「目前只看到相关性，因果关系还不清楚」 |
| D | 动物实验或体外实验 | 「这个目前只在动物或细胞实验里看到，人身上还没验证」 |
| E | 专家意见或机制推测 | 「这个更多是理论推测，还没有直接证据」 |

**硬性规则**（`prompt.py` 的 `EVIDENCE_RULES`）：只有 D 或 E 级证据的说法，必须明确说「证据还不够，不能当结论」，不允许用肯定语气陈述。涉及菌株必须写到菌株号，不能只说「乳酸菌」。涉及剂量必须给单位、疗程和适用人群。

除 A–E 外，每块还带一个正交的 `authority` 字段（`meta-analysis` > `guideline` > `rct` > `cohort` > `animal` > `opinion`），由关键词抽取、最先命中者胜出，只参与检索加权，不直接展示给用户。

**语料规模**：`research/` 下 9 篇研究文档，重建索引后 **762 块**，其中带证据等级 369 块（48%）、法规块 102 块。

> 注意：仓库里 `knowledge/chunks.jsonl` 当前仍是早期 5 篇文档的 443 块产物，且对应的向量文件已随向量后端切换失效。见第 8 节。

## 6. 安全与合规边界

### 闸门一：输入报警症状（`RED_FLAGS`，15 组正则）

便血、黑便、呕血、体重下降、吞咽困难、持续呕吐、贫血、腹部包块、夜间症状、黄疸、发热伴腹痛、剧烈腹痛、脱水、消化道疾病家族史、排便习惯改变。

命中后分两种行为：

- **emergency**（命中 + 第一人称）：走 `ESCALATION_TEMPLATE` 固定话术直接返回。这是全系统唯一一段模型不参与生成的用户可见文本。
- **caution**（命中但非自述）：注入 `REFERRAL_INSTRUCTION`，要求模型区分「用户在描述自己症状」和「用户在问这个症状的科普」，前者把就医建议放最前面，后者正常科普但结尾提示。

### 闸门二：输出违规宣称（`BANNED_CLAIMS`，7 组正则）

对应《广告法》第十七条与《食品安全法》第七十三条：

| 模式 | 拦什么 |
|---|---|
| 治疗\|治愈\|根治\|痊愈\|药到病除 | 疾病治疗功能宣称 |
| 预防…病/癌/症/炎 | 疾病预防功能宣称（「预防接种」已排除） |
| 替代\|代替…药物/治疗/就医 | 宣称可替代医疗 |
| 无\|没有\|零…副作用 | 无副作用宣称 |
| 100%\|百分之百\|绝对有效\|保证治好 | 绝对化用语 |
| 特效\|神效\|秘方\|奇效 | 夸大功效 |
| 最好/最强的益生菌/产品/菌株 | 绝对化最高级 |

**逐句扫描，否定语境豁免。**「益生菌不能治疗肠炎」不算违规，「益生菌可以治疗肠炎」算。豁免靠 `_NEGATED` 匹配句内否定词（不能、不得、禁止、违法、并非、没有证据……）。

命中是**失败而不是警告**：带纠正指令重写，最多两轮，两轮不过就弃答。

### 就医边界与特殊人群

系统提示词强制要求：免疫抑制、危重症、中心静脉置管、短肠综合征、早产儿、化疗或器官移植后，使用益生菌前必须先咨询医生且要主动提醒。孕妇、哺乳期、婴幼儿、正在服药（尤其抗生素、免疫抑制剂）的用户，给建议时必须单独提示与医生确认。

### 每个 LLM 阶段的兜底

| 阶段 | 模型不可用时 |
|---|---|
| 分流 | `infer_filters` 提供确定性过滤条件，risk 取正则给的 floor，子查询退化为原问题 |
| 重排 | 回退到混合检索原序（已加权、已配额） |
| 作答 | 返回明确的「未配置模型」提示，不伪装成正常回答 |
| 实时检索 | 返回 `[]`，主链路继续 |

安全层完全不依赖模型，所以模型层全挂时急症判定照常工作——这一点已在无任何可用 provider 的环境下验证过。

## 8. 当前状态与已知问题

按严重程度排序。快照时间见文档开头。

### 8.1 阻塞项

**（1）索引当前不可用，必须重建。** 向量后端已从 OpenAI 切到本地 Ollama `bge-m3`，向量文件改为按后端分文件存（`vectors-<backend>.npy`）。`knowledge/` 下现在只剩一个早期的 `chunks.jsonl`（443 块，5 篇文档），没有任何可用的向量文件。`load_index()` 会直接报错：

```
当前向量后端 ollama:bge-m3 还没有建过索引。
请运行： python -m agent.index build
```

重建后是 762 块（9 篇文档）。重建前后 chunk 数变化很大，任何基于 443 这个数字的判断都要重新校准。

**（2）当前没有任何可用的作答 provider。** `llm.active_provider()` 返回 `None`：

- 本地 Ollama 的 **chat** 模型（默认 `qwen3:14b`）没有拉下来，`llm.ollama_up()` 为 False
- `llm.local_only()` 默认为 True（`MINGTU_LOCAL_ONLY` 未设置即视为开启），所以**不会回退到云端**
- 环境里也没有 `ANTHROPIC_API_KEY`

结果是检索层和安全层正常，但不生成回答。两条路二选一：`ollama pull qwen3:14b`，或显式 `export MINGTU_LOCAL_ONLY=0` 并配置云端 key。见 DEPLOY.md 第 3 节。

**（3）`local_only()` 在两个模块里语义相反。**

| 位置 | 默认值 | 行为 |
|---|---|---|
| `llm.local_only()` | `"1"` → **True** | 未设置即禁止云端作答 |
| `embed.local_only()` | `""` → **False** | 未设置即允许云端向量化 |

同一个环境变量 `MINGTU_LOCAL_ONLY`，同一个函数名，默认极性相反。当前实际后果就是一个自相矛盾的状态：**作答层拒绝把数据发往云端，向量层却会在本地后端不可用时把用户提问发给 OpenAI。** 如果本地优先的理由是数据出境合规（4.3 节），这个缺口必须堵上——两处应该统一到同一个判定函数。

**（4）检索层的查询向量化没有跟着换后端。** `retrieve.py:_embed_query` 仍然硬编码 OpenAI：

```python
from openai import OpenAI
self._client = OpenAI(api_key=openai_key())
resp = self._client.embeddings.create(model=EMBED_MODEL, input=[query])
```

它绕过了 `embed.py`。后果有两层：

- **维度不匹配**：索引若用 `bge-m3`（1024 维）建，查询向量却是 3072 维，`self.vectors @ v` 直接崩。`load_index` 的 manifest 检查拦不住这个——manifest 记录的是索引用了哪个后端，查询走的是另一条完全不受检查的路径。
- **合规缺口**：即使全本地建索引，每一次用户提问仍然会被发到 OpenAI。

修法是让 `_embed_query` 调 `embed.embed([query])`。这条必须和（3）一起修。

### 8.2 数据与语料

- **语料自带的 `[N]` 标记与本系统的引用编号冲突。** `research/*.md` 是 Perplexity 生成的，正文里带着它自己的引用标记 `[1][2][3]`，原样进了索引（早期 443 块的版本里，365 块含 `[N]`，其中 217 块含 1–8 范围内的编号，正好和本轮资料编号区间重叠）。模型可能照抄段落里的 `[13]`，被判成编造编号触发无谓重写；更糟的是照抄 `[3]`，落在合法区间内，校验通过但指向完全不相干的来源，且无法被发现。修法是在 `chunker.py` 里剥掉源文档自带的标记，或把本系统的引用格式改成不会撞车的形式。
- **约一半的块没有证据等级。** 重建后 369/762 带等级（48%，比早期 39% 有改善）。没等级的块 `GRADE_BOOST` 为 0，模型看到的标签是「未标注等级」，没法向用户传达可信度。原因是 `chunker._GRADE` 只认三种写法（`证据等级：A`、`（A级）`、`A级证据`）。
- **URL 抽取覆盖率低。** `_URL` 逐块跑，而 Perplexity 把参考文献集中放在文档末尾，绝大多数正文块里没有链接。结果是来源清单大部分条目没有可点验证的出处。
- **年份抽取有噪声。** `_YEAR` 匹配文中任意 4 位年份并取最大值，包括文献列表里提到的年份，不一定是这段结论本身的年份。
- **单一数据源。** 全部块来自同一批 Perplexity `sonar-deep-research` 输出，没有第二来源交叉校验，也没有人工审核记录。

### 8.3 逻辑缺陷

- **实时检索结果拿不到重排席位。** `core.gather` 里 live 段落的 `_score` 被硬编码为 `0.0`，而 pool 在切片前按分数降序排（`pool.sort(...)` 后 `rerank(query, pool[:24], ...)`）。实测单个子查询的本地检索就返回满 24 条，`pool[:24]` 被本地结果占满，实时段落在进入重排器之前就被切掉。只有本地召回不足 24 条时才有机会出现。这意味着 `live.py` 近似空转：花掉调用和超时预算，结果进不了答案。修法是给 live 段落一个能进候选池的初始分，或在切片时给它保留固定席位。
- **重写循环的 system 消息位置在 Anthropic 路径上不合法。** `core.py` 在一条 assistant 消息之后追加 `{"role": "system", ...}`。会话内 system 消息（claude-opus-5 支持，无需 beta header）要求跟在 `user` 消息之后，或跟在以服务端工具调用结尾的 assistant 消息之后；这里跟的是纯文本 assistant 消息，按接口约束会被拒绝，异常被吞掉后返回 `None`，用户看到「抱歉，这一轮没能生成回答」——**引用校验和合规校验的重写通道因此在 Anthropic 路径上实际不生效**。第一处 system 消息（紧跟 user 且位于末尾）位置是合法的。OpenAI 与 Perplexity 路径不受影响：`llm._fold_system_into_user` 会把它折进 user 消息。修法是把纠正指令改成 `user` 角色，或在 assistant 之后先补一条 user 消息。改完必须用真 key 验证重写循环真的转起来了。
- **多轮对话的安全筛查只看当前轮。** `screen_input` 只扫本轮 `query`。用户第一轮说「我最近大便有血」、第二轮只说「那我该吃什么益生菌」，第二轮不会命中报警症状，也不会重新升级。`answer()` 接受 `history`，但历史消息不参与安全筛查。
- **`mentions_self` 判据很粗。** 只匹配「我/自己/本人/最近/这几天/一直/老是/总是」。「便血最近很多人在问」会被误判成自述并升级。刻意偏向误报，但没有降级通道。
- **近重复抑制只看 `(source, heading)`。** 同一标题下不同小节内容差异较大时会被误抑制。
- **配额与 `top_n` 可能冲突。** 法规 3 席加人群 2 席共 5 席，`top_n=8` 时留给通用相关性的只有 3 席。

### 8.4 工程与可观测性

- **异常被静默吞掉。** `llm.py` 的每个 provider 分支都是 `except Exception: return None`，认证失败、限流、超时、拒答、参数错误在外部完全不可区分。这是当前最大的可观测性缺口。网页服务会把堆栈打进服务端日志，CLI 会打异常类型和消息，但模型层内部的失败原因拿不到。
- **一个测试失败。** `tests/test_chunker.py::test_regulatory_detection[可用于婴幼儿食品的菌种名单]`——`chunker._REGULATORY` 收了「可用于食品的菌种名单」但没收婴幼儿那一版。当前 156 passed / 1 failed / 18 xfailed。
- **`pytest` 不在 `requirements.txt` 里**，只存在于 `.venv`。
- **测试只覆盖 `safety.py` 和 `chunker.py`。** 「只升不降」的合并规则、引用校验、重写循环、provider 选择都没有测试。
- **`tools/research.py` 的 `key()` 不读环境变量也不读项目 `.env`**，只读 `~/Desktop/dev` 下的共享 `.env`。所以把 `PERPLEXITY_API_KEY` 填进项目 `.env`，实时检索这一路拿不到（作答回退那一路能拿到，走的是 `llm._read_key`）。`.env.example` 里已记录这个问题。
- **`index.py` 里的 `openai_key()` 和 `EMBED_MODEL` 已是历史残留**，只有 `retrieve.py` 还在用（见 8.1 第 4 条）。
- **索引重建是全量的**，加一篇研究文档也要重跑全部 762 块。
- **没有速率限制（网页层只有 3 并发的信号量）、没有会话持久化、没有成本追踪。**

## 9. 关键设计约束（改动时按这些衡量）

改代码前先确认没有破坏这七条。它们是这个产品的底线，不是优化项。

1. 急症判定绝不能只依赖模型。`safety.screen_input` 是确定性的，分类器只能升级不能降级。
2. 每个 LLM 阶段都必须有确定性兜底。模型层挂了安全层仍要工作。
3. 回答必须逐条标注来源编号，编造编号视为严重缺陷。
4. 资料不足时必须弃答，不能用不对题的内容凑答案。
5. 所有面向用户的文本必须是中文，且不能有 AI 腔（不要「希望对您有帮助」这类）。
6. 不得出现中国《广告法》《食品安全法》禁止的健康宣称。
7. 定位是科普与就医导航，不是诊断工具。

特别提醒第 6 条：**为了让某个回答通过而放宽 `BANNED_CLAIMS`，是错误的修法。** 问题出在生成端就在生成端修（改提示词、改重写指令），不要动闸门。闸门放宽一次，之后所有回答的合规底线都跟着降了。
